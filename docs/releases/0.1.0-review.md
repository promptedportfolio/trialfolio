## User outcome

Compare existing DataMiner screen-backtest results with their supplied configurations, and understand exactly what differs ([OUT-01](../spec.md#users-and-outcomes)).

## Included scope

- `trialfolio review <config> --out <dir>`: an offline comparison of two or more imported results against an explicit baseline.
- One verified DataMiner ScreenBacktest CSV export layout, procured and documented in R01-T01 and R01-T02. It is identified as `dataminer-screenbacktest-csv` version 1 and tied to the DataMiner build it was observed from.
- One attached DataMiner ScreenBacktest YAML configuration per result, which is optional. Trial Folio interprets the documented ScreenBacktest settings in it. The source-derived observation in [ADR 0001](../adrs/0001-python-and-portfolio123-integration.md#verification-notes) is that the export itself contains no settings, so this configuration is the only source of settings.
- Reported summary metrics, settings, coverage dates, and differences, normalized to CSV.
- A self-contained, script-free HTML report and an inspectable manifest.
- `trialfolio demo --out <dir>` (proposed name): writes synthetic demo inputs and reviews them, entirely offline.
- `trialfolio --version`, `trialfolio license [--accept]`, and the one-time [license acknowledgment](../contracts.md#license-acknowledgment) ([D-17](../spec.md#decisions)).
- [JSON summaries](../contracts.md#json-summary) on stdout with `--json`.
- A supported-format statement and a capability table in README.md, plus the license and notices.

## Explicit exclusions

- Any network access or provider call. The API arrives in [0.2.0](0.2.0-api-execution.md).
- Other export layouts, such as RankPerformance, RollingScreen, simulations, and exports from other DataMiner builds, unless they match the verified layout exactly.
- Interpreting the per-period `Results` rows and the returns in the `Time Series` section. Both are preserved in the source copy and described as "present, not interpreted". The only exception is that the series' dates are read to establish actual coverage.
- Reconstructing returns, drawdown histories, or confidence intervals from summary statistics, and any charts.
- DataMiner configurations that use iterations. They are preserved, and their settings are reported as not interpreted.
- Any facility for Compustat data ([D-16](../spec.md#decisions)). A configuration naming Compustat is preserved, and its vendor is flagged as unsupported and unverified.
- Statistical validation and trading readiness, which are reported as "Not assessed".

## Supported inputs and examples

**Review configuration.** The fields and rules are in [contracts.md, review configuration](../contracts.md#review-configuration). In the example below, the setting names in `intended_changes` are illustrative until R01-T02 fixes them.

```yaml
kind: review
schema_version: 1.0.0
title: Holdings 25 versus 50
purpose: Check whether doubling holdings changes risk as expected.
baseline: hold25
results:
  - label: hold25
    export: exports/hold25.csv
    configuration: configs/hold25.yaml
  - label: hold50
    export: exports/hold50.csv
    configuration: configs/hold50.yaml
    intended_changes:
      - setting: max_num_holdings
        reason: Doubling holdings is the change under review.
```

```text
trialfolio review comparison.yaml --out review/
```

**DataMiner export.** This is the layout verified in R01-T01. The pinned DataMiner source suggests a multi-section CSV with `Stats`, `Results`, and `Time Series` sections. That is not a compatibility claim until a real export confirms it.

**DataMiner configuration.** This is a ScreenBacktest YAML file with the settings documented in [DataMiner operation: ScreenBacktest](https://portfolio123.customerly.help/en/articles/14056-dataminer-operation-screen-backtest).

## Required behavior

1. **Validate before writing.** Validate the configuration against [contracts.md, review configuration](../contracts.md#review-configuration): at least two results, unique labels, a baseline that names a result, existing files, intended changes that name known settings and aren't on the baseline, and no unknown or duplicate keys. Detect every export's layout from its structure (section labels and header rows), not from its file name. Nothing is written until all inputs pass.
2. **Preserve sources.** Copy each export and configuration byte for byte into `sources/<label>/`. Record the `artifact_id`, size, original file name, import time, layout identifier and version, parser version, and provenance `user_supplied`.
3. **Import metrics.** Read the summary statistics for the screen and the benchmark as metrics. Each metric has the unit, definition, and source precision fixed by the verified layout mapping, and origin `reported`.
4. **Interpret settings.** Read the documented ScreenBacktest settings from the attached configuration and map them to normalized names and critical categories ([contracts.md, settings and differences](../contracts.md#settings-and-differences)).
   - A documented setting that is absent takes DataMiner's documented default as an `inferred` value, citing the article and the date it was checked. It is flagged when it falls in a critical category; for example, an absent Slippage is shown as inferred 0 in the costs category.
   - An absent End Date is `unknown` unless the time-series dates establish it. Trial Folio never assumes a run date.
   - An absent Vendor is FactSet, DataMiner's documented default, recorded as `inferred` ([D-16](../spec.md#decisions)). An explicit `FactSet` is `user_supplied`. Any other value is recorded as written and flagged as an unsupported vendor.
   - Settings Trial Folio does not interpret are listed as not interpreted.
5. **Establish coverage.** Record the requested start and end dates from the configuration. If the verified layout has a time series, record the actual first date, last date, and number of periods from it. Flag any mismatch between requested and actual coverage.
6. **Compare with the baseline.**
   - Classify every setting as `same`, `intended_change`, `unexplained_mismatch`, or `unknown`.
   - Flag `unexplained_mismatch` and `unknown` values in critical categories.
   - Compute metric differences only between comparable values, expressing percent-to-percent differences in percentage points.
   - Show benchmark-relative metrics side by side without a difference when the benchmarks differ.
7. **Keep missing values explicit.** A missing metric or setting is unavailable, with a reason code, and never zero. A value that cannot be parsed stays in the source copy and becomes `unparseable_in_source`.
8. **Respect precision.** Never display or store more decimal places than the source. A difference uses the smaller of its operands' decimal counts. A difference in the Precision setting itself is flagged.
9. **Render the report** following [contracts.md, reports](../contracts.md#reports). Sections the evidence cannot support are shown as unavailable. Statistical validation and trading readiness read "Not assessed".
10. **Run offline.** Make no network access, including in the demo, report rendering, and logging.
11. **Log locally.** Write logs to `<out>/logs/` only, containing no configuration values, formulas, metrics, or file contents.
12. **Require the license acknowledgment** before processing any data, as [contracts.md, license acknowledgment](../contracts.md#license-acknowledgment) specifies.
13. **Write the normalized tables** exactly as [contracts.md, normalized tables](../contracts.md#normalized-tables) specifies, including the flag codes.

## Failure and incomplete-data behavior

| Situation | Behavior |
|---|---|
| Export does not match the verified layout | `import.unsupported_layout`, exit 3. The message names the supported layout. No output is written. |
| Export matches the layout but a section or header is missing | `import.malformed`, exit 3. No output is written. |
| A single value cannot be parsed | Unavailable with `unparseable_in_source`, a warning on stderr, and the command continues |
| No configuration attached to a result | Allowed. All of that result's settings are `unknown`, and the report says a settings comparison is unavailable for it. |
| Configuration uses iterations or unknown DataMiner keys | Preserved; the affected settings are listed as not interpreted |
| Configuration names Compustat or another unsupported vendor | Preserved and reviewed. The vendor is flagged as unsupported and unverified in the data-source category. |
| Two results have identical export bytes | Warning, flagged in the report as a possible mistake |
| Output directory exists and is not empty | `output.not_empty`, exit 4. Nothing is modified. |
| A write fails partway | `storage.write_failed`, exit 4. No manifest is written, so the output is visibly incomplete. |
| Misspelled key in the review configuration | `config.invalid`, exit 3. The message names the key. |
| No license acknowledgment | `license.not_acknowledged`, exit 2. Nothing is written. |

## Acceptance criteria

Each criterion is paired with a synthetic fixture unless noted otherwise.

| ID | Criterion |
|---|---|
| R01-AC01 | A two-result review writes the manifest, normalized CSVs, and report, and exits 0 |
| R01-AC02 | Source copies are byte-identical to the inputs, manifest hashes match, and original file names are recorded |
| R01-AC03 | An attached configuration with settings Trial Folio cannot interpret is preserved, and those settings are listed as not interpreted |
| R01-AC04 | Different benchmarks are displayed and explicitly flagged, and benchmark-relative metrics are not differenced across them |
| R01-AC05 | A missing metric is unavailable, with a reason, in the CSV and the report, never zero |
| R01-AC06 | A saved comparison is rendered with network access disabled, and the demo completes with network access disabled |
| R01-AC07 | An unsupported layout fails with `import.unsupported_layout` and exit 3, and no output directory is created |
| R01-AC08 | A declared intended change is shown as intended, and an undeclared difference in a critical category is flagged as an unexplained mismatch |
| R01-AC09 | An absent End Date is unknown, never today. An absent Slippage is an inferred documented default with a citation, flagged in the costs category. |
| R01-AC10 | Differences carry explicit units, with percentage points for percent metrics, and never exceed source precision |
| R01-AC11 | The report contains the concise notice, the full notice, and the license identifier. It has no `<script>` elements, event-handler attributes, or external resource references, and it shows "Not assessed" for statistical validation and trading readiness. |
| R01-AC12 | A non-empty output directory fails with exit 4 and nothing in it changes |
| R01-AC13 | A misspelled key in the review configuration fails with `config.invalid` and exit 3 |
| R01-AC14 | Clean install: in a new virtual environment, the built wheel installs, and `trialfolio demo --out <dir>` runs offline with `TRIALFOLIO_ACCEPT_LICENSE` set and exits 0 |
| R01-AC15 | Run at DEBUG level with canary values in configurations and exports, no canary appears in any log file, and logs are written only under `<out>/logs/` |
| R01-AC16 | The importer accepts the local reference exports from R01-T01, recorded as verification evidence, and the synthetic fixture that mirrors their structure. The reference files are never committed. |
| R01-AC17 | stdout carries only the result, and `--json` emits exactly one JSON object; warnings and errors go to stderr |
| R01-AC18 | A result without a configuration is reviewed, with all its settings unknown and the report stating why |
| R01-AC19 | The wheel contains LICENSE, CONTACT.md, THIRD_PARTY_NOTICES.md, and the disclaimers. Package metadata declares `LicenseRef-NSPRL-1.0`, with no MIT or OSI classifier. |
| R01-AC20 | An absent Vendor resolves to FactSet as an inferred default with a citation. An explicit FactSet is user-supplied. A configuration naming Compustat is flagged as an unsupported vendor. Results with different vendors are flagged in the data-source category. |
| R01-AC21 | Without an acknowledgment, a non-interactive `review` fails with `license.not_acknowledged` and exit 2, and writes nothing. `--version`, `--help`, and `trialfolio license` still work. |
| R01-AC22 | `trialfolio license --accept` writes a record containing only the four documented fields, and later runs don't ask again. A changed license identifier or notice version asks again. |
| R01-AC23 | `TRIALFOLIO_ACCEPT_LICENSE` set to the exact `<license_id>/<notice_version>` acknowledges for that process without writing a record. Any other value is rejected. |
| R01-AC24 | The normalized tables match [the contract](../contracts.md#normalized-tables): UTF-8 without a byte-order mark, columns in the documented order, an empty value only with a reason, documented flag codes, and deterministic row order |
| R01-AC25 | `--json` emits exactly one object matching [the JSON summary](../contracts.md#json-summary), both on success and on failure, for example an unsupported layout |
| R01-AC26 | A duplicate key, an intended change on the baseline, or an unknown setting name fails with `config.invalid`. A declared change whose values are equal is flagged `intended_change_not_observed`. |

**R01-T01 details.** The owner installs the current DataMiner build and records its version. Using the minimal configurations described below, the owner produces three exports with "Save output":

- **A** is the baseline.
- **B** is A with a different Max Num Holdings.
- **C** is A with a different Benchmark.

The configurations and run record are in [reference/dataminer-screenbacktest/](../../reference/dataminer-screenbacktest/README.md) and are committed. The record captures the date, the DataMiner version, and the credits used. The exports go in that folder's `exports/` subfolder, which is git-ignored. "Save credentials" stays unticked, because that option writes a plaintext `config.ini`.

**Minimal reference configurations for R01-T01.** Drafted 2026-10-01 in [reference/dataminer-screenbacktest/](../../reference/dataminer-screenbacktest/README.md). Every setting that matters is explicit: Start Date, End Date, Benchmark, Slippage (non-zero), Max Num Holdings, Rebalance Frequency, Precision, Universe, one simple rule, and a single-formula ranking. Rankings given as nodes or XML are not used, because they would create or overwrite `APIRankingSystem` in the account. The owner reviews the proposed universe, rule, and ranking before running. A screen backtest costs 5 API credits per operation, so the three exports are expected to cost about 15 credits. The absent-setting behavior is tested with synthetic configurations and costs nothing.
