## The user guide's walk-through

On 2026-10-04, at the owner's request, each step of [the user guide](../user-guide.md) ran in a new clone of `main` at 90dce6e, from a workspace `trialfolio init` set up, with the license record and the per-user logs in temporary directories. Every check the guide gives passed but one, and the walk-through found four smaller problems. The [release's changes after sign-off](0.1.0-api-execution.md#changes-after-sign-off) give each, and its fix.

- **FAT and exFAT.** `trialfolio demo` onto exFAT and FAT32 disk images failed with `output.not_empty`, not the `storage.write_failed` the guide gives. With the fix, `demo` onto both fails with `storage.write_failed` at `configuration.yaml`, before any request, and leaves `plan.json`, the claim's log, the attempt's empty directories, and their AppleDouble files.
- **Step 7's live run.** With the owner present, and their approval of 5 credits, `trialfolio run` sent the starter `screen.yaml` once, with `--approve` and the credentials injected for that command alone. It exited 0, with one attempt, one provider request, and the 5 credits Portfolio123 reported. Its report and tables passed step 8's checks, and `trialfolio report` re-rendered it offline, without credentials, with the same text, and left the run unchanged. A scan after the run found the API key in no file. Neither credential appears in the logs, the report, the normalized tables, the plan, the configuration, or the attempt's records. Its output stayed in a temporary directory, not in `reference/`.
- **Not exercised:** the keychain on the owner's login keychain, for which a separate keychain with invented values stood in; the prompt for one shell session; a ranking by name or ID in a live run; Portfolio123's error responses; and a response whose coverage differs from the requested dates.

## Limitations

- Everything ran on one Mac. The Windows paths are checked only from CPython's source and Microsoft's documentation, as R01-T08 recorded, and the pseudo-terminal tests rely on `TIOCSCTTY`, which Linux has but which hasn't run there.
- The live check ran once, with one configuration. Whether a failed request is charged is still unknown, because no request failed.
