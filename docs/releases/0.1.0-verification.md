# Release 0.1.0: verification record

This is the record that [release 0.1.0's verification commands](0.1.0-api-execution.md#verification-commands-and-expected-evidence) call for. It gives each command's date, versions, and outcome, and the evidence for each acceptance criterion. R01-T16 created it. It records only what was run: a command that hasn't run says so.

## Environment

All of these ran on 2026-10-04, on the branch `test/remaining-tests`, based on `main` at 9a6d277. The live check ran at its commit bfecffe. Since then, only what it does with a command still running after 600 seconds has changed: it interrupts the command, as Ctrl-C would, instead of killing it. That path hasn't run live.

- **Machine:** macOS 26.6.2 (25G83), arm64. Nothing has run on Linux or Windows yet.
- **Tools:** Python 3.12.13, uv 0.12.3, pytest 9.1.1, ruff 0.16.10, pyright 1.1.414.
- **Packages:** `p123api` 3.1.0, `requests` 2.34.2, and `urllib3` 2.8.0, the [verified versions](../contracts.md#plan-contents); `pydantic` 2.13.5, `pydantic-core` 2.46.5, `PyYAML` 6.0.3, and `rfc8785` 0.1.4, as `uv.lock` pins them. `simplejson` isn't installed.

## Limitations

- Everything ran on one Mac. The Windows paths are checked only from CPython's source and Microsoft's documentation, as R01-T08 recorded, and the pseudo-terminal tests rely on `TIOCSCTTY`, which Linux has but which hasn't run there.
- The live check ran once, with one configuration. Whether a failed request is charged is still unknown, because no request failed.
