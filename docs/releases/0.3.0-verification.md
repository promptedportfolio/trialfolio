## The user guide's experiment workflow

On 2026-10-12, R03-T12 ran the [user guide](../user-guide.md#11-run-an-experiment)'s experiment workflow, its sections 11 and 12, under 0.3.0, on the branch `docs/r03-t12-documentation`, based on `main` at c177e77, on macOS 26.6.2 with Python 3.14.8. It used a temporary workspace that `trialfolio init` set up, with the documented example, `example.yaml`, and a smaller experiment, `default-only.yaml` with a budget of 3. It had no credentials and no budget for live calls, so each command ran in a new process through the test launcher, as the interface tests run them: the CLI's entry function, given the endpoint of the fake Portfolio123 server on localhost, which answered each request from a script, with the committed `complete.json` response, a 400, or a 503. The installed command never takes an endpoint. Every value it returned is invented, and nothing from the walk-through is committed. Each check the guide gives passed:

  - A budget below the number of cases, and a variant of `universe`, failed with `config.invalid`, exit 3, with the messages the guide describes.
  - Approved without credentials, it failed with `provider.auth_failed`, exit 5, sent nothing, and created no output directory.
  - Approved, with a 400 to `liquidity-100m` and a 503 to `holdings-50`, it authenticated once, sent the five requests, and exited 6 with `execution.partial`. The message listed both cases, with the option that repeats each. The directory held the files the guide lists, with tables for the three cases that succeeded and none for the other two.
  - Once every case had succeeded, the run exited 0, and stdout said "Experiment completed", with the session, its report, the plan hash, and that statistical validation and trading readiness are not assessed.
  - In sessions 1 and 7's manifests, the planned cases equaled those succeeded, failed, skipped, unknown, and not yet run, and each report gave the same counts. Each case's `metrics.csv` and `settings.csv` were labeled with its `case_id`.

- **Section 12, resuming, repeating, and revising:**
  - Run again without credentials, the same command resumed plan 1, sent nothing, wrote `sessions/2/`, and exited 6 again, since both cases awaited a repeat. Its summary gave each one's `repeat_attempt_id`, the one in the message.
