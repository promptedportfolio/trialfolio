## User outcome

Run one supported screen backtest and keep the relationship between its settings and its results ([OUT-01](../spec.md#users-and-outcomes)).

## Included scope

- **`trialfolio run <config> --out <dir>`.** Plan, approve, execute, capture, normalize, and report one long-only stock screen backtest through `p123api`'s `screen_backtest`.
- **A narrow `kind: screen` configuration** covering an inline screen only. The supported settings are limited to those verified in R01-T01 to R01-T03:
  - universe, rules, and ranking (an existing system by name or ID, or a single formula)
  - maximum holdings, benchmark, start date, end date, rebalance frequency, transaction price, slippage, point-in-time method, and precision
  - data vendor: FactSet only, and optional ([D-16](../spec.md#decisions))
- **A plan shown before execution.** It includes its hash, a request budget, and the categories of data sent. Execution requires the approved hash ([REQ-04](../spec.md#enduring-requirements)).
- **Attempt records, saved before any normalization.** They hold the redacted request, the full decoded response, timing, the wrapper version, and provider metadata (`cost`, `quotaRemaining`).
- **Normalized output:** `metrics.csv` and `settings.csv` ([contracts.md, normalized tables](../contracts.md#normalized-tables)), a manifest, and a self-contained, script-free HTML report.
- **`trialfolio report <run-dir> --out <dir>`.** Re-renders a saved run's report offline from its archived records ([INV-05](../spec.md#enduring-invariants)).
- **`trialfolio demo --out <dir>` (proposed name).** Writes a synthetic example run, clearly labeled synthetic, and renders its report entirely offline.
- **Other commands and output:**
  - `trialfolio --version`
  - `trialfolio license [--accept]`
  - the one-time [license acknowledgment](../contracts.md#license-acknowledgment) ([D-17](../spec.md#decisions))
  - [JSON summaries](../contracts.md#json-summary) on stdout with `--json`
- **Packaging:** a supported-inputs statement and capability table in README.md, plus the license and notices.

## Explicit exclusions

- **Other screen types:** saved screens by ID; short, long/short, or hedged methods; ETF screens.
- **Ranking definitions given as nodes or XML**, which would change `APIRankingSystem` in the account.
- **Other data vendors:** Compustat, or any vendor other than FactSet ([D-16](../spec.md#decisions)).
- **Other operations:** rolling screens, rank performance, simulations, and any other endpoint.
- **Automatic retries** of a charged request.
- **More than one case.** Experiments arrive in [0.3.0](0.3.0-experiments.md).
- **Comparing runs**, which arrives in [0.2.0](0.2.0-review.md).
- **The per-period series** in the response, beyond preserving it and reading its dates for coverage.
- **Charts, and any reconstruction** of returns, drawdown histories, or intervals from summary statistics.
- **Any DataMiner integration** ([ADR 0005](../adrs/0005-build-on-the-portfolio123-api-only.md)).
- **Statistical validation and trading readiness,** which are reported as "Not assessed".

## Supported inputs and examples

```text
trialfolio run screen.yaml --out runs/baseline/
trialfolio report runs/baseline/ --out reports/baseline/
trialfolio demo --out demo/
```

The `kind: screen` structure is not specified yet; see [Completing this specification](#completing-this-specification), step 3. A single-formula ranking is recommended, because the configuration then records it completely. A ranking by name or ID refers to a mutable object in the account.

## Required behavior

1. **Validate strictly.** Reject any setting outside the verified subset before a plan is built. The start date, end date, benchmark, and slippage MUST be explicit; there is no default of "today" and no default of zero cost.
   - The vendor MAY be omitted. Trial Folio then leaves it out of the request, and the plan shows FactSet as an inferred default. The response doesn't report the vendor (R01-T01), so it can't be confirmed.
   - A vendor other than FactSet fails with `config.invalid`.
2. **Show the plan.** Show the resolved request, what will be sent to Portfolio123, the request budget, the documented credit cost, and the plan hash.
   - Portfolio123 documents a cost of 5 credits for a screen backtest. Whether failed requests are charged is unverified, so failed and uncertain attempts are treated as possibly charged.
   - Execute only with the matching approved hash.
3. **Require the license acknowledgment** before any request, as [contracts.md, license acknowledgment](../contracts.md#license-acknowledgment) specifies.
4. **Make attempts visible.** Configure the wrapper for one HTTP attempt per call. Write a durable `running` attempt record before sending. Request decoded JSON (`to_pandas=False`).
5. **Capture first.** Save the complete decoded response and provider metadata durably before any normalization or validation of its content. A response that later fails validation is kept and flagged.
6. **Redact.** The saved request contains no credentials. Never log, serialize, or save wrapper exception or response objects. Keep only the status code and a sanitized message.
7. **Normalize.**
   - Write `metrics.csv` and `settings.csv` exactly as [contracts.md, normalized tables](../contracts.md#normalized-tables) specifies.
   - Values Trial Folio sent or captured are `verified`.
   - A metric the response lacks is unavailable with a reason, never zero.
   - Never store or display more decimal places than the response carries.
8. **Record mutable references.** For a ranking or universe given by name or ID, record an external reference. Record whether its definition was snapshotted, and label reproducibility incomplete when it wasn't.
9. **Label costs honestly.** No commission parameter is documented, so commission is recorded as "not modeled by this provider path", never as zero.
10. **Establish coverage.** Record the requested start and end dates and, where the response has a dated series, its actual first date, last date, and number of periods. Flag any mismatch.
11. **Report.** Render the report following [contracts.md, reports](../contracts.md#reports), with execution details. Statistical validation and trading readiness read "Not assessed".
12. **Re-render offline.** `trialfolio report` rebuilds the report from a saved run without network access. `trialfolio demo` makes no network access.
13. **Log locally.** Write logs to `<out>/logs/` only. They contain no credentials, configuration values, formulas, response contents, or results.

## Failure and incomplete-data behavior

| Situation | Behavior |
|---|---|
| No license acknowledgment | `license.not_acknowledged`, exit 2; nothing is written |
| Misspelled key, or a setting outside the verified subset | `config.invalid`, exit 3; no request is sent. If the provider itself rejects a setting: `provider.unsupported_capability`, exit 5. |
| Missing credentials | `provider.auth_failed`, exit 5, before any request |
| Authentication rejected (400, 401, 402, or 406) | `provider.auth_failed`, exit 5. The message is actionable, for example "invalid ID/key" or "paying subscription required". The attempt is recorded as `failed`. |
| Quota exhausted (402 on a request) | `provider.quota_exceeded`, exit 5. The attempt is `failed`, possibly charged. |
| Connection error before a response | The attempt is `failed`, with its charge status unknown |
| Read timeout, or the process dies after sending | The attempt is `unknown`: reported as uncertain and never retried automatically. `provider.outcome_unknown`, exit 5. |
| Response fails validation | The response is saved, and the attempt is `succeeded` for capture. The result is flagged `provider.response_invalid`, exit 5, and the report shows the normalized result as unavailable. |
| Approval missing, or the hash doesn't match | `plan.approval_required`, exit 2; no request is sent |
| Output directory exists and isn't empty | `output.not_empty`, exit 4; nothing is modified |
| A write fails partway | `storage.write_failed`, exit 4. No manifest is written, so the output is visibly incomplete. |
| `trialfolio report` is given something that isn't a complete run | `input.not_a_run`, exit 3; nothing is written |

## Acceptance criteria

Each criterion is paired with a synthetic fixture or a test double at the provider boundary unless noted otherwise. R01-T05 names each pairing.

| ID | Criterion |
|---|---|
| R01-AC01 | The plan shows the resolved request, budget, and hash, and no request is sent without the matching approval |
| R01-AC02 | A misspelled or unsupported setting is rejected with `config.invalid` before any request |
| R01-AC03 | The complete available response, including `cost` and `quotaRemaining` when present, is saved before normalization, and the manifest's hashes match the saved files |
| R01-AC04 | No credential canary appears in any artifact or log, including after a simulated authentication failure |
| R01-AC05 | Authentication, quota, unsupported-capability, and response-validation errors each give their documented code, exit code, and actionable message |
| R01-AC06 | A simulated read timeout records an `unknown` attempt that is not retried |
| R01-AC07 | The attempt log records exactly one attempt per HTTP request |
| R01-AC08 | `trialfolio report` re-renders a saved run with network access blocked, and the result matches the saved normalized data |
| R01-AC09 | A missing end date or slippage is a configuration error, never today or zero |
| R01-AC10 | A ranking given by name records an external reference with its snapshot status. A single-formula ranking is fully recorded. |
| R01-AC11 | An omitted vendor is left out of the request and shown in the plan as FactSet, an inferred default. An explicit `FactSet` is sent as given. `Compustat` fails with `config.invalid` before any request. |
| R01-AC12 | A metric missing from the response is unavailable, with a reason, in the CSV and the report, never zero. No value exceeds the response's precision. |
| R01-AC13 | The report contains the concise notice, the full notice, and the license identifier. It has no `<script>` elements, event-handler attributes, or external resource references. It shows "Not assessed" for statistical validation and trading readiness. |
| R01-AC14 | The normalized tables match [the contract](../contracts.md#normalized-tables): UTF-8 without a byte-order mark, columns in the documented order, an empty value only with a reason, documented flag codes, and deterministic row order |
| R01-AC15 | A non-empty output directory fails with exit 4, and nothing in it changes |
| R01-AC16 | Clean install: in a new virtual environment, the built wheel installs, and `trialfolio demo --out <dir>` runs offline with `TRIALFOLIO_ACCEPT_LICENSE` set and exits 0. The demo's run is labeled synthetic. |
| R01-AC17 | At DEBUG level, with canary values in credentials, configuration, formulas, and response contents, no canary appears in any log file, and logs are written only under `<out>/logs/` |
| R01-AC18 | stdout carries only the result. `--json` emits exactly one object matching [the JSON summary](../contracts.md#json-summary), both on success and on failure. Warnings and errors go to stderr. |
| R01-AC19 | The wheel contains LICENSE, CONTACT.md, THIRD_PARTY_NOTICES.md, and the disclaimers. Package metadata declares `LicenseRef-NSPRL-1.0`, with no MIT or OSI classifier. |
| R01-AC20 | Without an acknowledgment, a non-interactive `run` fails with `license.not_acknowledged` and exit 2, and writes nothing. `--version`, `--help`, and `trialfolio license` still work. |
| R01-AC21 | `trialfolio license --accept` writes a record containing only the four documented fields, and later runs don't ask again. A changed license identifier or notice version asks again. |
| R01-AC22 | `TRIALFOLIO_ACCEPT_LICENSE` set to the exact `<license_id>/<notice_version>` acknowledges for that process without writing a record. Any other value is rejected. |
| R01-AC23 | `trialfolio report` given an incomplete or non-run directory fails with `input.not_a_run` and exit 3 |
| R01-AC24 | A recorded real integration check with the owner's account succeeds within its budget, and its output is archived locally and re-rendered offline. It is opt-in and never part of default CI. |
