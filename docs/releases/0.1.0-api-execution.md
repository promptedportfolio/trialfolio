### The owner's confirmation

On 2026-10-01 the owner confirmed what R01-T05 added: R01-AC30 and R01-AC31, the extension of R01-AC29, `TRIALFOLIO_LOG_LEVEL`, the fixed endpoint, `configuration.yaml` in the run layout, and the list of defaults below.

Two reviews of R01-T05 then made these changes, which the owner checks at sign-off:

- **The endpoint and the environment.** No Trial Folio setting changes the endpoint. Trial Folio also turns off `requests`' environment settings, so no proxy, certificate-bundle, or `.netrc` setting applies, and 0.1.0 supports no proxy. `SSLKEYLOGFILE` is ignored, with a warning ([credentials](../contracts.md#credentials)). New R01-AC32 checks this, and R01-AC26 drops its proxy case. The owner accepted this on 2026-10-01, including that 0.1.0 supports no proxy.
- **Version checks.** Installed versions are read from package metadata, and the imported `requests` and `urllib3` must report the same `__version__` ([plan contents](../contracts.md#plan-contents)).
- **Strict validation.** Configuration models validate in strict mode, so no value is coerced ([Pydantic conventions](../contracts.md#pydantic-conventions)).
- **Report links.** A report links only to its own sections and, by relative path, to the run's artifacts ([reports](../contracts.md#reports)).
- **The CLI's entry function** gained parameters for tests only: the endpoint, the request timeout, the clock, and the factory for the output's `ArtifactStore`. The installed command never passes them.
- **The timeout.** Trial Folio sets the request timeout to 300 seconds, explicitly ([timeouts](../contracts.md#http-exchanges)).
- **R01-AC31.** Coverage that can't be established isn't flagged as a mismatch. The report says it couldn't be established.
- **R01-AC13.** The concise notice links in-page to the full notice, which carries the license name, `license_id`, and `notice_version` (DSC-03).
- **The screen configuration.** `universe` and `benchmark` must be non-empty.
- **The live check** runs only with the owner present, who grants its network access. That's the owner's own decision.
- **Authentication's cost.** The evidence is two measured authentications, not three, and the 15-credit total covers the requests only.
- **Up markets.** A period with a benchmark return of zero is verified to count as an up market.
- **The defaults below** add the disclaimers.md entries and the Pydantic conventions.

## User outcome

Run one supported screen backtest and keep the relationship between its settings and its results ([OUT-01](../spec.md#users-and-outcomes)).

## Included scope

- **`trialfolio run <config> --out <dir>`.** Plan, approve, execute, capture, normalize, and report one long-only stock screen backtest through `p123api`'s `screen_backtest`.
- **A narrow `kind: screen` configuration** covering an inline screen only. The supported settings are limited to those verified in R01-T01 to R01-T05:
  - universe, rules, and ranking (an existing system by name or ID, or a single formula)
  - maximum holdings, benchmark, start date, end date, rebalance frequency, transaction price, slippage, point-in-time method, and precision
  - data vendor: FactSet only, and optional ([D-16](../spec.md#decisions))
  - currency: USD only. It's sent on every request and isn't a configuration key.
- **A plan shown before execution.** It includes its hash, a request budget, and the categories of data sent. Execution requires the approved hash ([REQ-04](../spec.md#enduring-requirements)), given interactively or with `--approve <plan-hash>`.
- **Attempt records, saved before any normalization.** They hold the redacted request, the full decoded response, timing, each HTTP exchange the call made, the versions of `p123api`, `requests`, and `urllib3`, and provider metadata (`cost`, `quotaRemaining`).
- **Normalized output:** `metrics.csv` and `settings.csv` ([contracts.md, normalized tables](../contracts.md#normalized-tables)), a manifest, and a self-contained, script-free HTML report.
- **`trialfolio report <run-dir> --out <dir>`.** Re-renders a saved run's report offline from its archived records ([INV-05](../spec.md#enduring-invariants)).
- **`trialfolio demo --out <dir>`.** Writes a synthetic example run, clearly labeled synthetic, and renders its report entirely offline.
- **Other commands and output:**
  - `trialfolio --version`
  - `trialfolio license [--accept]`
  - the one-time [license acknowledgment](../contracts.md#license-acknowledgment) ([D-17](../spec.md#decisions))
  - [JSON summaries](../contracts.md#json-summary) on stdout with `--json`
- **Packaging:** a supported-inputs statement and capability table in README.md, plus the license and notices.

## Explicit exclusions

- **Other screen types:** saved screens by ID; short, long/short, or hedged methods; ETF screens.
- **Ranking definitions given as nodes or XML**, which would change `APIRankingSystem` in the account.
- **Other data vendors:** Compustat, or any vendor other than FactSet ([D-16](../spec.md#decisions)).
- **Other operations:** rolling screens, rank performance, simulations, and any other endpoint.
- **Automatic retries** of a charged request.
- **A proxy.** Trial Folio ignores the environment's proxy, certificate-bundle, and `.netrc` settings, so that nothing can redirect or expose the credentials ([credentials](../contracts.md#credentials)).
- **More than one case.** Experiments arrive in [0.3.0](0.3.0-experiments.md).
- **Comparing runs**, which arrives in [0.2.0](0.2.0-review.md).
- **The per-period series** in the response, beyond preserving it and reading its dates for coverage.
- **Charts, and any reconstruction** of returns, drawdown histories, or intervals from summary statistics.
- **Any DataMiner integration** ([ADR 0005](../adrs/0005-build-on-the-portfolio123-api-only.md)).
- **Statistical validation and trading readiness,** which are reported as "Not assessed".

## Required behavior

1. **Validate strictly.** Reject any setting outside the verified subset before a plan is built. The start date, end date, benchmark, and slippage MUST be explicit; there is no default of "today" and no default of zero cost.
   - The vendor MAY be omitted. Trial Folio never sends it, because the endpoint documents no vendor parameter. Whether it's omitted or given as `FactSet`, the plan shows FactSet as an inferred default. The response doesn't report the vendor (R01-T01), so it can't be confirmed.
   - A vendor other than FactSet fails with `config.invalid`.
2. **Show the plan.** Build and show the plan that [contracts.md, plans and approval](../contracts.md#plans-and-approval) specifies: the resolved request, every resolved setting, what will be sent to Portfolio123, the request budget, the documented credit cost, and the plan hash.
   - Portfolio123 documents a cost of 5 credits for a screen backtest. Whether failed requests are charged is unverified, so an attempt whose request may have reached Portfolio123 is treated as possibly charged, whatever its outcome, and one whose request never did isn't ([contracts.md, possibly charged](../contracts.md#http-exchanges)).
   - Execute only with the matching approved hash: typed confirmation on an interactive terminal, or `--approve <plan-hash>`.
   - Follow that section's order of steps, so a plan can be reviewed without credentials, and no output is created and nothing is sent before approval.
3. **Require the license acknowledgment** before any request, as [contracts.md, license acknowledgment](../contracts.md#license-acknowledgment) specifies.
4. **Make attempts visible.** Configure the wrapper for one HTTP attempt per call, and record each HTTP exchange through Trial Folio's transport adapter, which also allows one exchange per call ([contracts.md, HTTP exchanges](../contracts.md#http-exchanges)). Authenticate with a separate call first. Then write the durable start record, and only then send the backtest request, at most once. Write the attempt record once, when the attempt ends ([contracts.md, execution outcomes](../contracts.md#execution-outcomes-and-attempts)). Request decoded JSON (`to_pandas=False`).
5. **Capture first.** Save the complete decoded response and provider metadata durably before any normalization or validation of its content. A response that later fails validation is kept and flagged.
6. **Redact.** The saved request contains no credentials. Never log, serialize, or save wrapper exception or response objects. Keep only the status code and a sanitized message. The exchange record holds only each exchange's method, path, result, and status. The only raw body kept is a backtest 200 the wrapper can't decode, saved as `response.raw`; an authentication body is never kept.
7. **Normalize.**
   - Write `metrics.csv` and `settings.csv` exactly as [contracts.md, normalized tables](../contracts.md#normalized-tables) specifies.
   - Values Trial Folio sent or captured are `verified`.
   - A metric the response lacks is unavailable with a reason, never zero.
   - Never store or display more decimal places than the response carries.
8. **Record mutable references.** For a ranking or universe given by name or ID, record an external reference. Record whether its definition was snapshotted, and label reproducibility incomplete when it wasn't.
9. **Label costs honestly.** No commission parameter is documented, so commission is recorded as "not modeled by this provider path", never as zero.
10. **Establish coverage.** Record the requested start and end dates and, where the response has a dated series, its actual first date, last date, and number of periods. Flag any mismatch.
11. **Report.** Render the report following [contracts.md, reports](../contracts.md#reports), with execution details. Statistical validation and trading readiness read "Not assessed".
12. **Re-render offline.** `trialfolio report` rebuilds the report from a saved run without network access. `trialfolio demo` makes no network access.
13. **Log locally.** `run` writes its logs to `<out>/logs/` once it has claimed the output directory. Before then it holds them in memory, and writes them to the per-user log directory only after an internal error. Commands without an output directory, such as `trialfolio license`, log to the per-user log directory ([contracts.md, logging](../contracts.md#logging-and-local-diagnostics)). Logs contain no credentials, configuration values, formulas, response contents, or results.

## Failure and incomplete-data behavior

This table maps each situation to an outcome and an error code. [contracts.md](../contracts.md#execution-outcomes-and-attempts) defines the terms it uses, and the table doesn't restate them:

- **[HTTP exchanges](../contracts.md#http-exchanges):** each exchange's result, `response` with a status, `not_connected`, or `interrupted`, how a provider failure is classified, and when an attempt is possibly charged.
- **[Endings that decide the error code](../contracts.md#endings-that-decide-the-error-code):** a caught user interrupt gets `command.interrupted`, exit 130, and a storage failure `storage.write_failed`, exit 4. The rows below still give the outcome and whether it's possibly charged, but their error codes apply only to other endings. [Interrupts](../contracts.md#interrupts) says what an interrupt leaves at each stage.
- **[Uncertain completion](../contracts.md#uncertain-completion):** what a start record without an attempt record means.

| Situation | Behavior |
|---|---|
| No license acknowledgment | `license.not_acknowledged`, exit 2; nothing is written |
| Misspelled key, or a setting outside the verified subset | `config.invalid`, exit 3; no request is sent. If the provider itself rejects a setting: `provider.unsupported_capability`, exit 5. |
| The installed `p123api`, `requests`, or `urllib3` isn't a [verified version](../contracts.md#plan-contents), or `simplejson` is importable | `environment.unsupported`, exit 3, before the plan is shown. No output is created, and no request is sent. The package pins all three exactly, so this happens only in an environment changed by hand. |
| Missing credentials | `provider.auth_failed`, exit 5, before any request |
| On Linux or macOS, the output directory is on a file system without hard links, such as exFAT | `storage.write_failed`, exit 4, at the first atomic write, `configuration.yaml`, before any request. No manifest is written, so the output is visibly incomplete ([contracts.md, artifact storage](../contracts.md#artifact-storage)). |
| Trial Folio's own authentication call gets a 400, 401, 402, 403, or 406 | `provider.auth_failed`, exit 5. The message is actionable, for example "invalid ID/key" or "paying subscription required". The attempt is `failed`, and not possibly charged: the backtest request wasn't sent. |
| Trial Folio's own authentication call gets a status below 500, other than 200 and the statuses above, such as a 204, 3xx, 404, or 429 | `provider.request_rejected`, exit 5. The message gives the status, and says it isn't a credentials problem. The attempt is `failed`, and not possibly charged. |
| Trial Folio's own authentication call gets a 5xx, or is `not_connected` or `interrupted` | `provider.unavailable`, exit 5. The attempt is `failed`, and not possibly charged. |
| The backtest request gets a 400, for example for an unsupported value | `provider.unsupported_capability`, exit 5. The message includes Portfolio123's sanitized message. The attempt is `failed`, possibly charged. |
| The backtest request gets a 402: quota exhausted | `provider.quota_exceeded`, exit 5. The attempt is `failed`, possibly charged. |
| The backtest request gets a 401 or 403 | `provider.auth_failed`, exit 5. The wrapper's re-authentication is refused as a second exchange, so the request isn't resent, and the message is the one for a [refused exchange](../contracts.md#http-exchanges): it gives the status, and says Portfolio123 refused the request's authorization right after Trial Folio authenticated. The attempt is `failed`, possibly charged. |
| The backtest request gets a status below 500, other than 200 and the statuses above, such as a 3xx, 404, or 429 | `provider.request_rejected`, exit 5. The message gives the status, and Portfolio123's sanitized message when the wrapper's exception message carries one. A redirect that `requests` would follow is refused as a second exchange, and gets the message for a [refused exchange](../contracts.md#http-exchanges). The attempt is `failed`, possibly charged. |
| The backtest request is `not_connected`: the name lookup failed, or the connection was refused or timed out | `provider.unavailable`, exit 5. The attempt is `failed`, and not possibly charged: the request didn't reach Portfolio123. |
| The backtest request is `interrupted`, for example by a reset, a read timeout, or a body that broke off, or it gets a 5xx | The attempt is `unknown`: possibly charged, and never retried automatically. `provider.outcome_unknown`, exit 5. |
| The backtest request gets a 200 that the wrapper can't decode | The body is saved as `response.raw`, labeled undecoded ([contracts.md, HTTP exchanges](../contracts.md#http-exchanges)), and the attempt is `succeeded` for capture, possibly charged. The result is flagged `provider.response_invalid`, exit 5, as in the validation row below. |
| The user interrupts the command, for example with Ctrl-C | `command.interrupted`, exit 130. The outcome, and what the command leaves, are as [contracts.md, interrupts](../contracts.md#interrupts) says. |
| The backtest call fails in a way no row above covers | `unknown` and `provider.outcome_unknown` if the attempt is possibly charged. Otherwise `failed`, with `internal.unexpected`. |
| The process is killed, for example by a power loss | No error code is recorded. A start record without an attempt record is `running`, as [contracts.md, uncertain completion](../contracts.md#uncertain-completion) says. |
| Response fails validation | The response is saved, and the attempt is `succeeded` for capture. The result is flagged `provider.response_invalid`, exit 5, and the report shows the normalized result as unavailable. |
| Approval missing or refused, or the hash doesn't match | `plan.approval_required`, exit 2. The plan hash is shown, with the full plan on a terminal. No output is created, and no request is sent. |
| Output directory exists and isn't empty when the command starts | `output.not_empty`, exit 4, before the plan is shown; nothing is modified |
| Another process writes to the output directory before `run` claims it | `output.not_empty`, exit 4, before any request. `run` removes only what its claim created, as [contracts.md, claiming the directory](../contracts.md#cli-behavior) says, so the other process's files are untouched. |
| A write fails partway | `storage.write_failed`, exit 4, even after the backtest request was sent. The attempt's outcome follows the rows above: a 200 whose response wasn't saved durably is `unknown`, possibly charged ([contracts.md, endings that decide the error code](../contracts.md#endings-that-decide-the-error-code)). No manifest is written, so the output is visibly incomplete. |
| `trialfolio report` is given something that isn't a complete run | `input.not_a_run`, exit 3; nothing is written |

## Required outputs

This is the final run layout for 0.1.0. [contracts.md, artifact storage](../contracts.md#artifact-storage) shows it as a tree, and says how each file is written:

- `manifest.json` and `plan.json`
- `configuration.yaml`, the byte-for-byte copy of the screen configuration
- `cases/<case_id>/attempts/<attempt_id>/`, holding `started.json` (the start record, once authentication succeeded), `attempt.json`, `request.json` (redacted), and `response.json` (the decoded response), or `response.raw` for a 200 the wrapper couldn't decode
- `normalized/metrics.csv` and `normalized/settings.csv`
- `report.html`
- `logs/`

Also the [JSON summary](../contracts.md#json-summary) on stdout with `--json`, and the per-user acknowledgment record when the user acknowledges the license interactively or with `trialfolio license --accept`.

## Acceptance criteria

[Test pairing](#test-pairing) pairs each criterion with a named check, and with the fixtures and test doubles that check uses. R01-AC24 is the live check. R01-AC19 checks the built wheel, and R01-AC22 needs no fixture or double.

| ID | Criterion |
|---|---|
| R01-AC01 | The plan shows the resolved request, budget, and hash, and no request is sent without the matching approval. Each of these fails with `plan.approval_required` and exit 2, and creates no output: no `--approve` without an interactive terminal, a refused confirmation, and an abbreviated or different hash. The full matching hash runs without a prompt, and the manifest records `option`. Typing `approve` runs the plan that was shown, and the manifest records `interactive`. When stderr isn't a terminal, only the hash and the budget are shown, never the formulas. |
| R01-AC02 | A misspelled or unsupported setting is rejected with `config.invalid` before any request. So is a slippage with more than 4 decimal places, such as `0.00001`. |
| R01-AC03 | The complete available response, including `cost` and `quotaRemaining` when present, is saved before normalization, and the manifest's hashes match the saved files |
| R01-AC04 | No credential canary appears in any artifact or log, including after a simulated authentication failure |
| R01-AC05 | Authentication, unavailable-provider, quota, unsupported-capability, rejected-request, and response-validation errors each give their documented code, exit code, and actionable message. An unverified `p123api`, `requests`, or `urllib3` version, and an importable `simplejson`, each fail with `environment.unsupported` and exit 3 before the plan is shown. |
| R01-AC06 | A simulated read timeout records an `unknown` attempt that is not retried |
| R01-AC07 | A run records at most one attempt, and sends the backtest request at most once. The attempt record lists every HTTP exchange in order: Trial Folio's authentication call, then the backtest request. `counts.provider_requests` counts the backtest sends that may have reached Portfolio123, never authentication. |
| R01-AC08 | `trialfolio report` re-renders a saved run with network access blocked, and the result matches the saved normalized data |
| R01-AC09 | A missing end date or slippage is a configuration error, never today or zero |
| R01-AC10 | A ranking given by name records an external reference with its snapshot status. A single-formula ranking is fully recorded. |
| R01-AC11 | An omitted vendor and an explicit `FactSet` are both left out of the request, shown in the plan as FactSet, an inferred default, and resolve to the same case. `Compustat` fails with `config.invalid` before any request. |
| R01-AC12 | A metric missing from the response is unavailable, with a reason, in the CSV and the report, never zero. No value exceeds the response's precision. |

**What `scripts/check` runs.** It's a POSIX shell script, like the owner's other repositories', and stops at the first failure:

1. Check that the Git hooks are on, meaning `core.hooksPath` is `.githooks`. If not, fail and say to run `scripts/setup`. This step is skipped when the `CI` environment variable is set, because a CI job runs the checks itself and pushes nothing.
2. `uv lock --check`, so the lock file matches `pyproject.toml`.
3. `uv run ruff format --check .`, then `uv run ruff check .`
4. `uv run pyright`, strict for `src/trialfolio`
5. `scripts/schemas --check`
6. `uv run pytest`
7. `uv run pytest -m packaging`

The steps arrive in stages, so pushes during implementation aren't blocked. R01-T06 adds the script with every step except step 5, which R01-T07 adds with `scripts/schemas`. Until R01-T16, pytest's exit code 5, which means no tests were collected, counts as a pass in steps 6 and 7. R01-T16 removes that allowance, so from then on a missing test fails.

It doesn't run the `reference` or `live` tests, which need the owner's local data, or the owner's credentials and presence. Ruff and pyright are in a `dev` dependency group, as in the owner's other Python repositories ([D-02](../spec.md#decisions)). R01-T06 chooses their versions.

**Test configuration.** pytest registers the markers `packaging`, `reference`, and `live`, with `--strict-markers`, and deselects all three by default with `-m "not packaging and not reference and not live"`. A later `-m` on the command line replaces that default, which R01-T06 verifies.
