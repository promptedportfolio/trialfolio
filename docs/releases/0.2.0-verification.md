## The user guide's review workflow

On 2026-10-06, R02-T11 ran the [user guide](../user-guide.md#10-compare-runs-with-a-review)'s review workflow under 0.2.0, in a temporary workspace that `trialfolio init` set up, with two runs `trialfolio demo` wrote, since it has no credentials. Each check it could make passed:

- `trialfolio --help` lists `review`, and `review` without an acknowledgment fails with `license.not_acknowledged`.
- The review exits 0, says what stdout should, warns that the two results share one saved response, writes the files the guide lists, and leaves the runs unchanged.
- Run from another folder, with the configuration's path, it finds each run from the configuration's folder.
- A declared change whose values are the same is `same`, flagged `intended_change_not_observed`.
- The report names both results synthetic before any result, links only to the LICENSE at `v0.2.0`, Portfolio123's terms, and its own files, and shows no `run` path.
- A missing `run` directory fails with `input.not_found`, a run without a manifest with `input.not_a_run`, each naming the result and its `run` path, and an output directory that isn't empty with `output.not_empty`.

Two demo runs can't check what needs other settings, such as an intended change or an unexplained mismatch. The default suite checks those over runs built with the fake server.

## Limitations

- Everything ran on one Mac, as for 0.1.0. The Windows paths are checked only from CPython's source and Microsoft's documentation.
- The reference check reviewed the one run the live check wrote, which has a saved response. So its branch for a run without one, such as a run whose authentication failed, didn't run. `tests/core/test_differences.py` checks the same behavior with runs built over the fake server.
- Links that name the version's tag, such as a report's link to the LICENSE and the starter README's link to the user guide, give `v0.2.0`, so they work only once 0.2.0 is tagged.
