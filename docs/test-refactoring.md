## Goal

Three of the refactor's four criteria for readability apply to the tests, with two of the tests' own:

- **Long functions.** A function over about 50 lines has room to extract its setup, or to separate the behaviors it checks.
- **Repeated logic.** A helper, a piece of setup, or a check written in more than one place is written once, for reuse.
- **Mixed modules.** A test module that holds distinct groups of tests is separated along its seam.
- **The new structure.** The tests' names, imports, and shared helpers say where the code they reach is, now that the refactor has split it. Each test still goes through a public entry point ([verification expectations](../AGENTS.md#verification-expectations)), so a test module for each module of `src/` isn't a goal ([the new structure](#the-new-structure)).
- **What the tests check.** The missing tests are added, and each copy of a check that checks less than another copy checks what the strictest one does ([question 10](#open-questions)).

The fourth, large classes, finds nothing: no class under `tests/` has more than 13 methods ([the size of the work](#the-size-of-the-work)). The [findings](#findings) apply the criteria to the tests at f02e5d4. The track is done when each finding is resolved as its task gives, or declined with a reason recorded in this file.

## What it doesn't change

- **The code under test.** No task changes `src/`, `scripts/`, `schemas/`, or `manual/`. A defect a task finds in Trial Folio's code is reported to the owner, and fixed in a change of its own, as the refactor's "1 metrics" wording was.
- **The committed fixtures,** byte for byte, apart from three kinds of change. A missing test may add a fixture, which its task names, with its row in its directory's `README.md`. A strengthened check may add the line it reads to each fixture of its kind, with the `README.md`'s account of it, as item 5 of [copies that check less](#copies-that-check-less) adds a `# Value:` line ([question 11](#open-questions)). A fixture directory's `README.md` records the criteria its fixtures exercise and the test modules that exercise them ([REQ-11](contracts.md#fixtures)), so a task that renames such a module updates the README.
- **What each test checks.** Each test checks at least what it checked. A test moves, is renamed, or becomes one case of a parametrized test only as its task records, and no check is dropped. A task strengthens a check only where a finding names it.
- **The boundaries.** Test doubles stand in only at the boundaries [AGENTS.md](../AGENTS.md#verification-expectations) allows, and the default suite stays offline under the network guard.
- **The opt-in suites.** `-m packaging`, `-m reference`, and `-m live` select the same tests, at the paths the release files' verification commands and AGENTS.md's [development commands](../AGENTS.md#development-commands) give.

## Constraints

Every task respects these:

- **The tests nobody else can run.**
  - **Reference tests** run only on the owner's machine, where the reference data is. A task that changes one, or a helper it imports, runs them from its worktree, read-only, with `TRIALFOLIO_REFERENCE_DIR` naming the main checkout's `reference/`, as the refactor's RF-AC09 gives. It records the result, and none skips. It runs the mutations TS-AC05 gives for them there too ([question 13](#open-questions)).
  - **Live tests** need the owner's credentials, a budget of API credits, and the owner present. The three need budgets of 5, 10, and 19 credits. `tests/live/test_experiment.py` and `test_ranking.py` import their helpers from `test_screen_backtest.py`, so a change to those helpers reaches all three. A live test changes only in its imports and docstrings, which `scripts/check` checks, unless the owner approves a live run for it ([question 6](#open-questions)), and in the `noqa` TS-T09 puts on a function left over Ruff's limits ([question 12](#open-questions)).
  - Neither the `check` workflow nor a reviewer runs either kind.
- **The network guard.** `tests/support/network_guard/` is the pytest plugin that keeps the default suite offline. [Its row in 0.1.0's test pairing](releases/0.1.0-api-execution.md#test-pairing) says what it covers, and what a test must do to keep it. `tests/test_network_guard.py`'s 36 tests, 74 with their parameters, check it. It fails open: a change that broke a refusal would leave the rest of the suite passing, and some of its branches have no test, such as `subprocess.Popen`'s `executable=` and its two Windows branches. So no task changes it, unless the owner adds that to its row, apart from the `noqa` TS-T09 puts on each of its three functions over Ruff's limits ([question 12](#open-questions)).
- **The writers of the historical fixtures.** `tests/support/synthetic_experiment.py` writes the synthetic historical fixtures through the core. `tests/support/rewritten_fixtures.py` is the refactor's [check of the reports](refactoring.md#the-check-of-the-reports), which `python -m tests.support.rewritten_fixtures` runs. Both also run as scripts, outside pytest. A task that changes either, or a builder they use, runs that check on its base and on its branch, and the two writes give the same bytes, as RF-AC04 gives.
- **Types and lint.** `scripts/check` runs Ruff over `tests/`, and pyright over `tests/` in its standard mode, as `pyproject.toml` gives. Each task keeps both clean.
- **The traces.** Each test traces to a requirement, an acceptance criterion, or a corrected defect ([verification expectations](../AGENTS.md#verification-expectations)), and each test module's docstring holds the traces of its tests. A test that moves takes its trace with it, and each part of a separated module traces the tests it holds.
- **The documents that name the tests.** Each release file's test pairing says that its module names are part of its specification, and the four test pairings name test modules on 113 lines. The verification records name them on 99 more, as records of the commands that ran. AGENTS.md, contracts.md, and user-manual.md name five test modules and one test, and the fixtures' `README.md` files name test modules on 48 lines. A renamed or moved test is recorded in [where the tests moved](#where-the-tests-moved) ([question 4](#open-questions)).
- **Other open pull requests.** A task doesn't start while an open pull request changes the test modules it changes. Every implementation task of a release writes tests, and its specification tasks may change some: the one that completes the specification sets the version, and updates the tests that hold it by hand ([D-26](spec.md#decisions)). So this applies to each of a release's tasks as well as to the track's ([question 1](#open-questions)).
- **No live calls.** No task sends anything to Portfolio123, or needs credentials, unless the owner approves one ([question 6](#open-questions)).

### Copies that check less

Where a check is written more than once, some copies check less than others. Each is a weakness of the tests, not of Trial Folio's code, and each copy takes the strictest form when its repeat is written once ([question 10](#open-questions)):

1. **That a report loads nothing.** The core's run, experiment, and review copies check the declarations and every element and attribute that could load or run something. The interface's experiment and ranking copies leave out `embed`, `base`, `form`, `svg`, the `style` attribute, `meta http-equiv`, and the declarations; `tests/interface/test_report_content.py` and `test_review_report.py` check only `script`, `link`, event attributes, `src`, and `url(`; and `test_a_report_with_a_definition_keeps_the_notices_and_links_rules`, in `tests/core/test_ranking_report.py`, checks only `<script` and event attributes. So no report with a ranking definition gets the strict check.
2. **The outside links.** `test_a_report_with_a_definition_keeps_the_notices_and_links_rules` finds them by their scheme only, so a protocol-relative link, `//host`, would pass, and `tests/core/test_report.py` compares them as a set, so a duplicated link would pass, where `tests/interface/test_report_content.py` compares sorted lists.
3. **The closing section.** The interface's experiment and ranking copies don't check the terms link's text and address, and the run's and the review's don't check that the data statement comes before the full notice's `<details>`.
4. **"Not assessed."** No test checks that a report with a ranking definition says statistical validation and trading readiness aren't assessed. `tests/core/test_ranking_report.py` and `tests/interface/test_ranking_report.py` hold R01-AC13's other rules, but not that one.
5. **The screen configuration's rejections.** `rejection`, in `tests/contract/test_screen_configuration.py`, 36 call sites, never checks that the error's log message is its message, which the other kinds' copies do. And the 93 invalid screen configurations have no `# Value:` line, so their test checks only that the message names the key, where the experiment's, the review's, and the snapshot's invalid configurations give the value, and their tests check that the message doesn't hold it. The strengthening adds a `# Value:` line to each of the 93 files, with the `README.md`'s account of it ([question 11](#open-questions)).
6. **The snapshot configuration's invalid cases.** Its test checks that the message doesn't hold the value with `not in`, where the review's and the experiment's use `contains_value`, and it leaves out their scan for any long value of the file.

### The check of the tests

TS-T01 writes it, under `tests/support/`, with its own tests, as RF-T01 wrote the check of the reports ([question 5](#open-questions)). It does two things, and the task records in this file how to run each:

- **The inventory** lists the IDs of the tests each suite collects, by collecting only, so it sends nothing and needs no credentials or reference data, and compares the lists of the base and the branch with a map of the IDs the task changes. It lists each ID that's in only one of them and not in the map, and each test the map names that isn't there.
- **The mutations** apply each of a list of changes to a module of `src/`, in a worktree, each a piece of text and its replacement, run the tests the task names against each, and record which tests fail. It restores each file from a saved copy, never with `git checkout`, and removes `__pycache__` afterwards, since a change of the same size can leave stale bytecode that still runs. It compares the base's results with the branch's.
